# Known differences between the native #326 rules and ESLint 9.39.5 at its defaults. One per line:
# <rule id> | <language> | <reason>. Only real behaviour differences are listed; missing options are

ward:javascript/no-unused-labels | javascript | a label is treated as used when any break or continue with the same name appears in its text, including in a nested scope that shadows it
ward:typescript/no-unused-labels | typescript | same as the JavaScript rule
ward:javascript/no-octal-escape | javascript | ESLint parses octal escapes only in script mode; the fixtures are checked that way
ward:typescript/no-octal-escape | typescript | the TypeScript parser rejects octal escapes, so ESLint cannot run this fixture; Ward is the only reference
ward:javascript/no-nonoctal-decimal-escape | javascript | ESLint parses this escape only in script mode; the fixtures are checked that way
ward:typescript/no-nonoctal-decimal-escape | typescript | the TypeScript parser rejects the escape, so ESLint cannot run this fixture; Ward is the only reference
ward:javascript/no-useless-escape | javascript | a backslash before a dollar sign that precedes a brace in a template literal (the escape that ESLint accepts) cannot be written in the frontend fixtures: the frontend rejects the template, so that escape is not validated
ward:typescript/no-useless-escape | typescript | same as the JavaScript rule
ward:typescript/no-dupe-class-members | typescript | the TypeScript frontend does not parse static accessors (static get or static set), so a duplicate static accessor is not reported
