# Juliet Java 1.3 (NIST SARD 111, public domain) against Ward's Java security rules.
# A finding in a bad method is a true positive (tp, at most one per case), a bad case without one is a false negative (fn), and a finding in a good method is a false positive (fp).
# The taint rules follow wildcard imports of JDK and servlet types, calls between the methods of one file, and calls into the other files of the case (the a to e variants of one flow, given to the run as its project). The remaining false negatives are the files that only hold a sink or a source (b to e), flows through a field, an array, a container or a virtual call, and the cases that read from a class the rules do not model.
# A sink on a chained receiver such as response.getWriter() is matched by the text of the receiver. The hard-coded password and key rules follow a string literal through a variable of one method.
# The CWE-327 false positives are the good cases that call Cipher.getInstance("AES"), which the JCA documentation maps to ECB mode, so ward:java/ecb-mode is right.
