# The 16 challenge categories that OWASP Juice Shop v20.4.0 publishes (category of each entry of
# data/static/challenges.yml; the number is how many challenges the category has), against Ward's
# TypeScript and JavaScript security rules. Written by hand from the project's category list and
# from reading the application code at the places the rules report; not compared by a test.
# rule: whether a ward:typescript/* or ward:javascript/* security rule names the weakness.
# found: whether Ward reported at least one real instance (a tp of juice-shop-labels.txt).
# Ground truth stops at what a reader of the code can decide: a challenge solved by a request
# sequence, by the data in the database or by the browser is not decidable from the source.
#
# category | challenges | rule | found | note

Missed: the SQL injection of routes/search.ts:23, and the NoSQL $where injections of routes/trackOrder.ts:18 and routes/showProductReviews.ts:36, where the value passes through a call or a ternary that carries no taint; routes/chat.ts reports nothing. Not seen by any rule: code in a string handed to vm.runInContext (routes/b2bOrder.ts:23), a prompt injection into a chatbot.
