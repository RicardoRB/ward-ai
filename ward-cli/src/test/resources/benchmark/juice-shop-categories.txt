# The 16 challenge categories that OWASP Juice Shop v20.4.0 publishes (category of each entry of
# data/static/challenges.yml; the number is how many challenges the category has), against Ward's
# TypeScript and JavaScript security rules. Written by hand from the project's category list and
# from reading the application code at the places the rules report; not compared by a test.
# rule: whether a ward:typescript/* or ward:javascript/* security rule names the weakness.
# found: whether Ward reported at least one real instance (a tp of juice-shop-labels.txt).
# Ground truth stops at what a reader of the code can decide: a challenge solved by a request
# sequence, by the data in the database or by the browser is not decidable from the source.
#
# category | challenges | rule | found | note
Injection | 14 | yes | yes, 4 | eval, pug template and Content-Security-Policy header injection in routes/userProfile.ts and the SSRF of routes/profileImageUrlUpload.ts:24 (tp). Missed: the SQL injections of routes/login.ts:34 and routes/search.ts:23 (the sink is models.sequelize.query, a chained receiver the SQL sink does not match) and the NoSQL $where injections of routes/trackOrder.ts:18 and routes/showProductReviews.ts:36 (receiver db.ordersCollection); routes/chat.ts:150 was not analysed (syntax error). Not seen by any rule: code in a string handed to vm.runInContext (routes/b2bOrder.ts:23), a prompt injection into a chatbot.
XSS | 9 | yes | yes, 5 | bypassSecurityTrustHtml of the login IP (frontend last-login-ip.component.ts:40) and the four coding-challenge snippets. Not analysed because of syntax errors: search-result.component.ts:113 and :146, track-result.component.ts:49, about.component.ts:120, administration.component.ts:74 and :92. Server-side stored XSS needs the data flow through the database.
Sensitive Data Exposure | 17 | partly | yes, 5 | hard-coded TOTP secrets in test/api/2fa.test.ts. Missed: the hard-coded HMAC key and private key of lib/insecurity.ts (not analysed, syntax error). The rest is exposed files, logs and API responses, which are not code weaknesses a rule can name.
Broken Access Control | 13 | no | n/a | missing authorization checks, IDOR and path traversal. Ward has no path traversal rule for TypeScript or JavaScript, so routes/fileServer.ts, routes/logfileServer.ts and routes/quarantineServer.ts are not covered.
Improper Input Validation | 12 | no | n/a | the validation that is missing is application logic.
Broken Authentication | 10 | partly | no | jwt-without-verification and hard-coded-secret exist; the weak MD5 password hash and the private key sit in lib/insecurity.ts, which was not analysed (syntax error), and routes/verify.ts, which was not analysed either.
Vulnerable Components | 9 | no | n/a | a dependency problem, found by the vulnerabilities gate and not by a source rule.
Miscellaneous | 6 | no | n/a | not a code weakness.
Security Misconfiguration | 5 | yes | yes, 5 | cors() with defaults (server.ts:184 and :185) and the session cookie without Secure, HttpOnly and SameSite (routes/updateUserProfile.ts:42). missing-frame-protection correctly stays silent: server.ts:189 enables helmet.frameguard().
Cryptographic Issues | 5 | yes | no | MD5 and Math.random use of lib/insecurity.ts is not analysed (syntax error); the only reports are an MD5 build checksum and Math.random in vendored code, which are not the challenges.
Observability Failures | 4 | no | n/a | missing monitoring and logging, not a code weakness.
Broken Anti Automation | 4 | no | n/a | missing rate limits and captchas that can be solved, which is application logic. insecure-random reports the captcha operands in routes/captcha.ts:14-19, which are public values (fp).
Security through Obscurity | 3 | no | n/a | not a code weakness.
Insecure Deserialization | 3 | yes | no | untrusted-deserialization reports nothing: the yaml.load of routes/fileUpload.ts:114 is inside a string handed to vm.runInContext, and the notevil eval of routes/b2bOrder.ts is a sandbox.
XXE | 2 | yes | no | xml-external-entities reports nothing: lib/xml.ts parses with libxml2-wasm through a dynamic import and a string run in a vm, which no rule follows.
Unvalidated Redirects | 2 | yes | no | untrusted-redirect did not see routes/redirect.ts: it was not analysed (syntax error). Its allowlist check is a substring test, which only a reader of the code would call weak.
