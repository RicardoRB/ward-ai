---
title: detect
description: Detect a supported project.
---

`ward detect` finds the supported project in the selected directory or its nearest parent, and
reports its language, build tool, framework, and project root. A project with more than one
language also gets a `Languages:` line that lists them all.

```sh
ward detect [-C <dir>]
```

## Options

| Option | What it does |
|---|---|
| `-C`, `--directory <dir>` | Run as if Ward were started in `<dir>`. |

## What is detected

- Gradle projects are recognized from `build.gradle` and `build.gradle.kts`.
- For Maven and Gradle projects, the language comes from the sources, not from the build file.
  Ward looks for `src/main/java` and `src/main/kotlin` in the project and its modules:
  - With Java sources, the language is Java, even when the build script is `build.gradle.kts`.
  - With only Kotlin sources, the language is Kotlin.
  - With both, the language is Java, and `Languages:` lists Java and Kotlin.
  - With no sources yet, the language is Java.
- The framework is labeled when the POM or a Gradle build script references its group:
  Spring Boot (`org.springframework.boot`), Quarkus (`io.quarkus`), Micronaut (`io.micronaut`),
  Helidon (`io.helidon`), Dropwizard (`io.dropwizard`), Javalin (`io.javalin`), and Ktor (`io.ktor`).
  If several match, the first in this list wins. The label is informational: Ward runs the same Java
  gates for every framework, including plain Java.
- TypeScript projects are recognized from `tsconfig.json`, and JavaScript projects from
  `package.json`.
- A TypeScript or JavaScript project's framework comes from its declared packages: Astro, Svelte,
  Vue, or Angular. Other frameworks, such as Next.js or NestJS, are reported as `None`; Ward runs the
  same gates for them. See [Node projects](/commands/init/#node-projects).
- Python projects are recognized from `pyproject.toml`, `setup.py`, `setup.cfg`, or a file whose
  name matches `requirements*.txt`. A Maven or Gradle build in the same directory keeps its
  precedence.

### Node package manager

For TypeScript and JavaScript, the first match decides the build tool:

1. The `packageManager` field of `package.json` (`npm@…`, `pnpm@…`, `yarn@…` or `bun@…`). Other
   values are ignored.
2. A lock file, in this order: `bun.lock` or `bun.lockb` (Bun), `pnpm-lock.yaml` (pnpm),
   `yarn.lock` (Yarn), `package-lock.json` (npm).
3. npm.

The `packageManager` field wins over a lock file that disagrees with it, because it is what Corepack
enforces. Deno is not supported.

### Node version

`detect` prints a `Node:` line with the target Node major version. The first source that gives a
number decides:

1. `.nvmrc`, such as `v20.11.1` → `20`. Aliases such as `lts/*` fall through.
2. `.node-version`.
3. The lower bound of `engines.node` in `package.json`, such as `^18.18.0 || >=20` → `18`.
4. `24`.

```text
Language:     TypeScript
Build tool:   pnpm
Framework:    None
Node:         22
Project root: /path/to/frontend
```

A malformed `package.json` is still detected; the manager then comes from lock files alone.

### Turborepo

A workspace root that holds `turbo.json` is a Turborepo project. `detect` prints a `Task runner:`
line for it, and a member of that workspace resolves to the root:

```text
Language:     TypeScript
Build tool:   pnpm
Framework:    None
Task runner:  Turborepo
Node:         22
Project root: /path/to/monorepo
```

### Python package manager

For Python, the first rule that matches decides the build tool:

1. uv, when `uv.lock` exists or `pyproject.toml` has a `[tool.uv]` table.
2. Poetry, when `poetry.lock` exists or `pyproject.toml` has a `[tool.poetry]` table.
3. PDM, when `pdm.lock` exists.
4. Hatch, when `pyproject.toml` has a `[tool.hatch]` table.
5. pip otherwise, including a `pyproject.toml` that has only a `[project]` table.

PDM and Hatch are detected, but `ward doctor` warns that Ward does not support them yet. A
`pyproject.toml` that does not parse is treated as having no tables, so a lock file still decides and
pip is the fallback.

### Python version

`detect` prints a `Python:` line with the target Python version as `major.minor`. The first source
that gives a version decides:

1. The first `major.minor` in the first line of `.python-version`, such as `3.12.4` → `3.12`, or
   `cpython-3.13` → `3.13`.
2. The lower bound of `requires-python` in `pyproject.toml`, such as `>=3.11,<4` → `3.11`.
3. `3.14`.

```text
Language:     Python
Build tool:   uv
Framework:    None
Python:       3.12
Project root: /path/to/api
```

## Modules and aggregators

Build modules belong to their aggregator, up to the Git top-level:

- A directory listed in an enclosing `pom.xml` `<modules>`, including profile modules, resolves to
  that aggregator.
- A Gradle build below an enclosing `settings.gradle(.kts)` resolves to that build.
- A package matched by the `workspaces` field of an enclosing `package.json` (an array, or
  `{ "packages": [...] }`), or by the `packages` list of an enclosing `pnpm-workspace.yaml`,
  resolves to that workspace root. This covers npm, pnpm, Yarn and Bun workspaces.
- A directory listed in the `[tool.uv.workspace] members` of an enclosing `pyproject.toml`, and not
  matched by its `exclude`, resolves to that uv workspace root. A member's `pyproject.toml` must
  exist for it to count.
- A nested build that no aggregator lists is its own project.

A workspace root is TypeScript when the root or any member has `tsconfig.json`, and JavaScript
otherwise.

Workspace patterns that start with `!` are ignored rather than applied, so a package they would
exclude is still grouped under the root.

### Python next to Node

A directory with both a Python marker and a `package.json` or `tsconfig.json` is two projects in
repository discovery: one Python and one TypeScript or JavaScript, both rooted at that directory. The
`detect` command started in that directory keeps reporting the Node project, as it did before, so
`check` and `init` there still use the Node project.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | A supported project was detected. |
| `1` | No supported project was detected. |
| `2` | Ward could not run. |
