---
title: rules
description: List, show, enable and disable analysis rules, and edit the selection in ward-rules.toml.
---

`ward rules` works with the analysis rules of the `ward` gate. It lists them, shows one, and turns
rules on or off in `ward-rules.toml`. The file's comments and formatting are kept.

```sh
ward rules list [--preset none|standard|strict] [--language <language>] [--category <category>] [--selected] [--format text|json] [-C <dir>]
ward rules show <id> [--format text|json]
ward rules enable <id>... [-C <dir>]
ward rules disable <id>... [-C <dir>]
```

## list

Lists every rule as one line: id, languages, category, presets and description, tab-separated. The
filters combine.

| Option | What it does |
|---|---|
| `--preset none\|standard\|strict` | Keeps the rules that the preset selects, with the same meaning as `[select] preset`. `strict` includes the `standard` rules. `none` keeps the rules that no preset selects, which only `include` can turn on. |
| `--language <language>` | Keeps the rules that cover the language, such as `java` or `python`. |
| `--category <category>` | Keeps the rules of one category, such as `sizes` or `naming`. |
| `--selected` | Keeps only the rules that `ward-rules.toml` selects. Without the file, the `standard` preset applies. |
| `--format text\|json` | Output format (default `text`). With `json`, stdout holds only the JSON document `{"rules": [...]}`. |

A filter value that is not known is a usage error, and the command names the valid values.

## show

Shows one rule: its description, languages, category, presets, and each option with its type, its
default and its bounds or allowed values. With `--format json`, stdout holds one object with the same
fields and an `options` array. An option's default is text in JSON; a list is joined with commas.

An unknown id exits with code `2` and suggests the closest known id, for example
`did you mean "ward:java/method-length"?`.

## enable and disable

`enable` adds each rule to `[select] include` in `ward-rules.toml`, and removes it from `exclude` if
it is there. `disable` adds each rule to `[select] exclude`, and removes it from `include`.

The command takes the id that Ward prints, `ward:<language>/<rule-name>`, and writes it into the file
as `<language>.<rule-name>`, the name `ward-rules.toml` uses: `ward:java/method-length` becomes
`"java.method-length"`.

- With no `ward-rules.toml`, the command creates one with `version = 1` and the `[select]` table.
- Comments, blank lines and the other keys of the file keep their place.
- Only the two lists change. `[rules.<language>.<rule-name>]` tables are never written.
- Every id is checked before anything is written. If one id is unknown, the file is not touched.
- The new text must be valid TOML. Otherwise the command refuses and leaves the file as it was.

```sh
ward rules enable ward:java/method-length
ward rules disable ward:java/no-field-di ward:java/no-standard-streams
```

## Exit codes

| Code | Meaning |
|---|---|
| `0` | The command completed. |
| `2` | An unknown id or filter value, an invalid `ward-rules.toml`, or a file that could not be written. |

See [`ward-rules.toml`](/configuration/ward-rules/) for the file format.
