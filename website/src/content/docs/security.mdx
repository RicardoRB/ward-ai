---
title: Security
description: Understand the trust boundary when running Ward.
---

`ward.toml` is executable trusted code. `ward check` runs its configured command with your
user's privileges in the project root. A malicious repository or pull request can therefore run
arbitrary programs. Only check repositories you trust, and treat configuration changes like build
scripts or CI pipelines. Do not run checks on untrusted pull requests outside a sandbox.

Ward invokes commands as an argument vector, never through a shell: shell chaining, expansion,
globbing, and redirection do not occur. This is **not a sandbox**—a wrapper such as `./mvnw` can
itself execute arbitrary build code. Child processes receive no stdin. Agent hooks and plugins also
execute repository-local configuration, so install integrations only in trusted projects.

Ward offers no dynamic scanning and makes no request to your application or to any other target
you configure. A scanner that you run as a plain `command` check is your
responsibility: you must be authorized to scan its target. The native `secrets` check
never puts a matched value in a finding, a report or a log: its findings carry only the rule, the
file, the line and the column, never the secret or a snippet of the source.

## Diagnostic logging

Normal runs remain quiet. With `--verbose`, Ward writes invocation-scoped diagnostics to the
provided stderr stream only. Logs exclude credentials, prompts, configuration and environment
contents, raw process arguments, and captured process output. Redirect stderr separately when
collecting diagnostics:

```console
ward --verbose check > report.txt 2> ward-diagnostics.log
```

## Network requests

Ward makes two kinds of network request of its own. The `vulnerabilities` check downloads the OSV
advisory archives of the ecosystems it finds, over HTTPS, and the request carries only the
ecosystem, an `ETag` and the client name; `ward check --offline` skips it, and the check is
enabled only when you choose it. The update check is the other one: after an interactive command, at most once a day, it
sends an HTTPS `HEAD` request to `https://github.com/RicardoRB/ward-ai/releases/latest` and
reads the release tag from the redirect.

The update check:

- The request carries no project, configuration, or environment data.
- `ward doctor` makes the same request every time it runs.
- Ward only prints a notice. It never downloads or replaces itself.
- Agent hooks, CI, and JSON or SARIF output never trigger the request.
- `WARD_NO_UPDATE_CHECK=1` turns it off everywhere, including in `doctor`. See
  [Environment variables](/reference/environment-variables/).
