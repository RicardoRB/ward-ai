---
title: Secret detection
description: Find committed secrets with Ward's native rules, with no tool to install.
---

The `secrets` check finds committed secrets inside Ward. It runs the rules of the Gitleaks 8.30.1
default configuration (222 rules) as data, reads text files itself, and starts no process (only the
opt-in history scan runs `git`). It replaces the `gitleaks` gate, so no executable has to be
installed, and edit hooks no longer report the gate as unavailable.

```toml
[checks.secrets]
enabled = true
profiles = ["default", "pre-commit", "pre-push", "ci", "edit"]
uses = "secrets"

[checks.secrets.paths]
match = ["**"]
full = ["ward-rules.toml"]
```

`ward init --gate secrets` writes this table. No preset selects the check: add it with `--gate`.
The check belongs to the fast phase, so it runs on every edit, like `ward-format`.

## What is scanned

- Every text file under the project root, including hidden folders such as `.github`.
- Not scanned: `target`, `build`, `dist`, `node_modules`, `mutants`, `.git`, `.ward`, files that Git
  ignores, and binary files (a NUL byte in the first 8 KiB). A file that is not valid UTF-8 is read
  as ISO-8859-1.
- With edited paths (`--path`, the edit hook, a commit), only those files.
- A file that cannot be read, or is larger than 8 MiB, is an execution error that names the file.
  Exclude it with `exclude-paths`; an excluded file is not read at all.

## Findings

A finding has the rule (`ward:secrets/<gitleaks-rule-id>`), the file, the line and the column where the match
starts, and a fixed message. It never holds the secret, any part of it, or any source text, and
neither do the JSON, SARIF and text reports or the diagnostics on stderr.

Each rule has its regex, keywords, entropy threshold, secret group, path filter and allowlists as
data, and the Gitleaks global allowlist (paths, regexes, stopwords) applies to every rule. A rule runs on a
file only when the file holds one of its keywords, and a match is reported only when the entropy of
its secret is above the rule's threshold. There is no inline suppression: a `gitleaks:allow` comment,
`.gitleaksignore` and `.gitleaks.toml` are not read. Use `exclude-paths` or the rule options.

Matching is line by line, in windows around keyword hits on lines longer than 4096 characters, except
for the five rules that span lines (`private-key`, `jwt-base64`, `curl-auth-header`,
`curl-auth-user`, `kubernetes-secret-yaml`). A rule that spends more than its work budget on a file
is an execution error that names the rule and the file; it is never a pass.

Gitleaks also decodes base64, hex and percent-encoded segments before matching; Ward does not.

## Options

| Where | Key | Meaning |
|---|---|---|
| `[checks.secrets]` | `exclude-paths` | Globs of paths that no secrets rule reads. |
| `[checks.secrets]` | `scan-history` | Also scan the lines every commit added. Default `false`. |
| `[checks.secrets]` | `history-since` | An ISO date (`2026-01-01`) that limits the history scan. Needs `scan-history`. |
| `ward-rules.toml` | `entropy` | A number that replaces the entropy threshold of one rule. |
| `ward-rules.toml` | `exclude-paths` | Globs of paths one rule leaves out. |

```toml
# ward-rules.toml
version = 1

[rules.secrets.generic-api-key]
entropy = 4.2
exclude-paths = ["docs/**"]
```

## History scan

With `scan-history = true` the check also matches the lines added by every commit reachable from any
ref, with the same rules and allowlists. A finding names the file, the line in that commit, and the
short commit id in its message. The history is read with `git log -p` in batches of 200 commits, is
not cached, and needs the full history: a shallow clone is an execution error, so use
`fetch-depth: 0` on GitHub Actions. To pay for it only in CI, add a second check:

```toml
[checks.secrets-history]
uses = "secrets"
scan-history = true
profiles = ["ci"]
```

## Moving from `gitleaks`

The `gitleaks` gate is removed, with no migration flag. A check that runs a `gitleaks` command is a
plain `command` check that reports its exit status and extracts no findings; `uses = "gitleaks"` is
rejected. Replace it with `uses = "secrets"`. The old gate scanned the history in `ci`; the native
check scans the working tree unless `scan-history` is set.
